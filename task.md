Ты — senior мобильный разработчик. Помоги спроектировать и написать
кроссплатформенное мобильное приложение (iOS + Android) для сканирования
визиток с ПОЛНОСТЬЮ ЛОКАЛЬНОЙ обработкой данных.

Жёсткие требования
Никаких внешних сервисов: фото, текст и любые данные НЕ покидают устройство.
OCR работает офлайн (on-device), без облачных API (н использовать
Cloud Vision, облачный ML Kit, OpenAI и т.п.).
Данные хранятся локально (встроенная БД или контакты устройства).
Приложение должно работать без интернета после установки
(модели OCR вшиты в сборку или докачиваются один раз и далее офлайн).
Стек
Фреймворк: Flutter (Dart).
OCR: Google ML Kit Text Recognition v2 (on-device) через пакет
google_mlkit_text_recognition. Поддержка латиницы и кириллицы.
Камера: пакет camera (превью, автофокус, вспышка, съёмка).
Выбор из галереи: image_picker.
Предобработка изображения: обрезка по границам визитки, коррекция
перспективы, повышение контраста (OpenCV через пакет opencv_dart
или нативная обёртка; опиши альтернативы).
Парсинг полей: регулярные выражения + эвристики для email, телефона,
URL, имени, должности, компании.
Локальная БД: Isar или sqflite (обоснуй выбор).
Экспорт: в контакты устройства (flutter_contacts), vCard, CSV.
Разрешения: камера, галерея, контакты — запрашивать корректно.
Что нужно от тебя
Архитектура приложения (слои: UI / бизнес-логика / данные),
структура папок, список экранов и навигация.
Список зависимостей (pubspec.yaml) с версиями и назначением каждой.
Схема пайплайна: фото -> предобработка -> OCR -> парсинг полей ->
экран проверки/редактирования -> сохранение.
Ключевые классы/сервисы и их ответственность (например, OcrService,
CardParser, CardRepository) с сигнатурами методов на Dart.
Логика парсинга полей: приведи regex и эвристики для телефонов
(с учётом форматов РФ/международных), email, сайта, имени, компании.
Обработка ошибок и краевых случаев: блики, тени, поворот текста,
несколько языков на одной визитке, пустой результат OCR.
Приватность: подтверди, что ML Kit on-device не шлёт данные,
как это проверить, что исключить из зависимостей.
Сборка и оптимизация размера: --split-per-abi, App Bundle,
вынос моделей, оценка итогового размера APK.
План тестирования на реальных фото визиток.
Пошаговый план реализации MVP (что делать в первую очередь).

# VCContacts

Flutter-приложение (Android + iOS) для сканирования визитных карточек с **полностью локальной** обработкой: фото, текст и визитки не покидают устройство. В рантайме нет ни одного сетевого вызова — в манифесте Android даже отсутствует разрешение `INTERNET`.

- Текущая версия: `0.1.0+1`
- UI — русскоязычный, Material 3
- Детальная документация: [ARCHITECTURE.md](ARCHITECTURE.md)

## Как это работает

```
Фото (камера/галерея) → кадрирование → предобработка → OCR на устройстве
→ парсинг полей → экран проверки (человек правит) → локальная БД → экспорт
```

Пошагово:

1. **Съёмка или выбор из галереи** — оба источника ведут в один и тот же поток обработки.
2. **Кадрирование** — рамку с угловыми маркерами можно тянуть пальцем (углы или весь прямоугольник), либо нажать «Без обрезки».
3. **Предобработка** (пакет `image`, плюс OpenCV для геометрии): если пользователь не задал ручную рамку, **OpenCV** (`opencv_dart`) пытается найти контур визитки (Canny → контуры → крупнейший выпуклый четырёхугольник) и выпрямляет её `warpPerspective` (best-effort: не нашли — работаем по исходному фото). Сразу после выпрямления **один раз** выполняется поворот по контуру прямоугольника: если карточка получилась «портретной» (высота больше ширины), кадр поворачивается на 90° до естественной горизонтальной ориентации. Направление текста здесь не участвует — логотип и отдельные надписи не могут сбить ориентацию. Далее: поворот по EXIF → обрезка по рамке → **маскировка графики/логотипа** (насыщенные области выбеливаются) → оценка яркости (предупреждения «очень тёмное» / «пересвечено — возможны блики») → ч/б, повышение контраста и нормализация уровней → уменьшение до 1600 px по длинной стороне, JPEG q92 во временный каталог. Дополнительно готовятся ещё два варианта: апскейл мелких кадров до ~1400 px с лёгкой подрезкой резкости и **бинаризация методом Оцу** (порог по гистограмме яркости — убирает градиенты теней и неравномерный фон мелкого текста).
4. **OCR на устройстве** — два движка, оба офлайн: Google ML Kit Text Recognition v2 (`TextRecognitionScript.latin`) и Tesseract 5 (`rus+eng`, tessdata_best вшиты в APK). ML Kit даёт чистую латиницу; Tesseract добирает кириллицу, которую ML Kit latin не видит. Tesseract запускается **многопроходно** — каждый вариант предобработки (base / upscale+sharpen / binary) × режимы сегментации `psm 3` и `psm 4`; качество прохода оценивается по средней уверенности слов (`x_wconf` из hOCR), выбирается лучший. **Основной режим — по областям** (`OcrService._recognizeRegions`): ML Kit размечает строки, кадр выравнивается по среднему наклону, найденные картинки/логотипы выбеливаются, каждый четырёхугольник строки выпрямляется, масштабируется до читаемого кегля и корректируется по цвету, после чего Tesseract `rus+eng` (`psm 7`) читает область. Русские и смешанные области фиксируются по результату Tesseract; английские — перераспознаются ML Kit и фиксируются его результат. Любой сбой режима областей возвращает полнокадровый резерв, описанный ниже. Ориентация визитки 90/270 в OCR **не меняется**: она задана предобработкой по контуру карточки; в режиме областей дополнительно устраняется только небольшой наклон строк по медиане углов ML Kit, поэтому строки не превращаются в вертикальные колонки, а логотип не влияет на выбор направления. **Сегментация мелкого текста**: по bbox слов лучшего прохода `FieldSegmenter` отбирает мелкие (высота ниже порога) и неуверенные слова, группирует их в блоки по вертикальному разрыву строк, **расширяет блоки до полных строк** (чтобы перенос адреса не разрывался), вырезает каждый блок из **цветного кадра** (с собственной коррекцией цвета сегмента и бинаризацией Оцу по его гистограмме) и из всех вариантов предобработки, **увеличивает** и распознаёт. Затем `BlockConsensus` («кворум заключений») выбирает для каждого блока лучший результат по уверенности **и** согласию проходов друг с другом — если один вариант ошибся, согласованное большинство его перевешивает. Восстановленный текст **заменяет** покрытые им строки на месте, сохраняя порядок чтения. Так индекс, дом, офис и другой мелкий текст читаются заметно надёжнее. В полнокадровом резерве `OcrService` выбирает между ML Kit и лучшим проходом Tesseract: кириллица важнее, при прочих равных — более полный текст. Прогресс на экране: предобработка → распознавание → разбор полей → готово, с подписью «Фото не покидает устройство».
5. **Парсинг полей** регулярками и эвристиками: имя, должность, компания, телефон, email, сайт, адрес. Всё, что не распозналось, попадает в редактируемое поле «Прочий текст с визитки» — ни одна строка не теряется.
6. **Проверка и правка** — человек подтверждает результат; видит предупреждения; неразобранный текст правится в поле «Прочий текст». «Сохранить» активно только если заполнено хотя бы одно из полей: имя, компания, телефон, email.
7. **Сохранение** в локальную sqflite-базу (`vc_contacts.db`, таблица `cards`, индексы под поиск и сортировку).

## Функциональность по экранам

### Список визиток (главный)
- Список сохранённых визиток: инициалы, имя/компания, подпись (должность · email), дата обновления; сортировка — по времени обновления (сначала новые).
- Поиск в приложении — по имени, компании, должности, мероприятию, тегам, телефонам, email и адресу (фильтрация в Dart без учёта регистра).
- Группировка списка через верхнее меню: по компании, мероприятию или тегу; карточка с несколькими тегами показывается в каждой группе своего тега. Все группы по умолчанию свёрнуты и разворачиваются тапом.
- Рядом с камерой и галереей — кнопка QR: показывает QR-код карточки с флагом **MyVcard** в формате vCard 4.0.
- Удаление: долгий тап на карточке или кнопка на экране деталей — с диалогом подтверждения.
- Pull-to-refresh, состояния «пусто» (с подсказкой) и «ошибка» (с кнопкой «Повторить»).
- Две FAB: галерея и камера; рядом QR-кнопка «моей» визитки; в верхнем меню — «Создать» для пустой карточки.
- Меню → «Экспорт всех в CSV» через системный share-sheet.

### Очереди распознавания и проверки
- Очередь распознавания сохраняется в приватном каталоге приложения: swipe-away, force-stop и перезапуск не теряют незавершённые и готовые задания.
- После запуска приложения очередь восстанавливается: прерванные OCR-задания ставятся в очередь заново, готовые снова доступны на проверку.
- Верхнее меню → **«Очистить очереди»** удаляет все несохранённые задания, черновики и временные файлы; сохранённые визитки не затрагиваются.

### Камера
- Превью, автофокус (встроен в контроллер), съёмка JPEG с увеличенной зоной затвора.
- Вспышка тремя режимами: выкл → факел → авто; переключение фронтальная/основная.
- Быстрый доступ к галерее прямо из экрана камеры.
- Разрешения: запрос с объяснением, переход в настройки при permanently-denied, альтернатива «можно из галереи» при отказе.
- Корректное поведение в фоне: контроллер отпускается на `inactive`, пересоздаётся на `resume` (иначе экран захвата «залипает»).

### Обрезка
- Рамка в нормализованных координатах (0..1) — переживает любое разрешение фото; зона захвата угла 44 px; минимальный размер рамки 15%.
- Кнопки: «Без обрезки» и «Сканировать».

### QR-визитки
- Перед кадрированием камера и галерея проверяют фото на QR с `BEGIN:VCARD`.
- Если QR содержит vCard 3.0/4.0, поля (`FN/N`, `ORG`, `TITLE`, `TEL`, `EMAIL`, `URL`, `ADR`, `CATEGORIES`, `NOTE`) разбираются и карточка сразу сохраняется в БД.
- Кадрирование, обрезка и OCR для такой карточки не запускаются; переносятся только поля из QR.
- Обычное фото без vCard продолжает идти в кадрирование и распознавание.

### Ход сканирования
- Четырёхшаговый индикатор (предобработка → распознавание → разбор → готово).
- Ошибка → «Повторить» (тот же снимок с той же рамкой) или «Закрыть»; экран сбоя **не пропадает**.
- Пустой OCR — не авария: открывается ручной ввод с баннером «Текст не распознан — заполните карточку вручную».
- **Диагностика OCR** — раскрывающаяся панель на экране проверки (и на экране сбоя): что вернул ML Kit и каждый проход Tesseract (вариант предобработки, psm) — число строк и символов, флаг кириллицы, уверенность в процентах, первые 200 символов распознанного текста или текст ошибки, кого выбрал сервис. Раньше сообщение мелькало и экран заменялся — теперь диагностику можно прочитать и приложить к обращению.
- **Выгрузка диагностики** (кнопка с иконкой бага на экране проверки/сбоя) — сохраняет в **публичную папку Download** телефона (`/storage/emulated/0/Download/VCContacts/diagnostics/<штамп>/`), видимую файловым менеджером: `summary.txt` (метрики + поля + полный текст), `hocr.html` и `words.csv` (слова с bbox и уверенностью), а также `<поле>.jpg` — вырезки областей изображения напротив каждого распознанного поля. На Android 11+ при первом нажатии запрашивается разрешение «Доступ ко всем файлам»; без него — тихий фолбэк в каталог приложения.

### Проверка/редактирование
- Десять полей: имя, должность, компания, телефон, email, сайт, адрес, заметки, **прочий текст с визитки**, теги.
- Пустые поля выглядят пустыми: примеры-подсказки не подставляются, чтобы не выдать нераспознанное за распознанное.
- Баннеры-предупреждения (о качестве фото, нескольких телефонах и т.п.).
- Фото визитки закреплено сверху и не прокручивается вместе с полями; «Увеличить» не нужен — фото открывается тапом.
- Возле поля «Заметки» — запись, прослушивание и удаление голосовой заметки; внизу формы — фото владельца и диагностика OCR.
- Неразобранные строки автоматически попадают в редактируемое поле «Прочий текст с визитки» — ничего не теряется.
- Защита от потери данных: при «назад» с несохранёнными правками — диалог «Не сохранять?»; индикатор сохранения на кнопке.

### Карточка (просмотр)
- Шапка с инициалами, именем, подписью и датой обновления.
- В правом верхнем углу фото визитки — кнопка QR: vCard 4.0 текущей карточки для сканирования другими.
- Флаг **MyVcard** (только одна карточка) включается в метаданных карточки и на форме редактирования.
- Экспорт: «В контакты» (системный Contact Provider) и «vCard» (share-sheet).
- Тап по любому полю — копирование значения в буфер обмена.
- Редактирование и удаление из этого же экрана.

### Экспорт
- **В контакты устройства** (`flutter_contacts`): имя/фамилия разбиваются, организация/должность, телефон (как на визитке — `phoneRaw`), email, сайт, адрес, заметки. Запрос разрешения с rationale, обработка permanently-denied.
- **vCard 3.0** (`N`, `FN`, `ORG`, `TITLE`, `TEL`, `EMAIL`, `URL`, `ADR`, `NOTE`, `REV`) — файл во временном каталоге, отправка через системный share-sheet.
- **CSV всех визиток**: UTF-8 с BOM (Excel открывает кириллицу), разделитель `;`, кавычки экранируются.

## Что распознаётся

| Поле | Как определяется |
|---|---|
| Email | regex; очистка конечной пунктуации |
| Телефон | кандидаты по regex → фильтры (7–15 цифр, отсев лет и индексов) → нормализация в E.164 с приоритетом РФ-форматов (`+7…`, `8…`, `999…`, городские со скобками); исходная строка сохраняется в `phoneRaw` |
| Сайт | явный `https://`/`www.` или «голый» домен с известным TLD + защита от `ACME Corp.` → `acme.co` |
| Адрес | словари `ул/пр/наб/…` и `street/ave/blvd/…` + 6-значный почтовый индекс РФ; срезаются осколки рамок (`\|9 \|`, `a`) в начале/конце; адрес, перенесённый на две строки, склеивается; режим работы (`9.00 - 17.00`) уходит в «прочий текст» |
| Имя | скоринг строки (два слова с заглавных, сплит «Имя — Должность» и т.п.) |
| Должность/компания | подстрочные словари ru/en + организационные формы (`ООО/ЗАО/LLC/Ltd/…`) |

Краевые случаи: найдено несколько телефонов — сохраняется лучший по приоритету, остальные — в предупреждении; «Не удалось выделить поля» — ручная правка.

## Хранение

- sqflite, файл `vc_contacts.db` в песочнице приложения; схема v7 (миграции добавляют `otherText`, `event`/`ocrText`/фото, несколько телефонов/Telegram, голосовые заметки, `tags` и флаг `myVcard`).
- Поля: имя, должность, компания, телефон (`phone` E.164 + `phoneRaw`), email, сайт, адрес, заметки, **теги** (`tags` JSON-массив), **MyVcard** (`myVcard`), **прочий текст с визитки** (`otherText`), путь к фото, даты создания/обновления.
- Поиск — фильтрация в Dart по всем текстовым полям и тегам; сортировка `updatedAt DESC`.

## Приватность

- В `AndroidManifest.xml` **нет разрешения `INTERNET`** — приложение физически не может открыть сокет.
- ML Kit работает через on-device API, Tesseract — локальная C++-библиотека с моделями в APK; облачный ML Kit, Firebase, аналитика и http-клиенты в зависимостях отсутствуют.
- Проверить можно через `adb shell dumpsys package com.vccontacts.app`, tcpdump на USB-мосте или прокси (Charles/Proxyman): 0 исходящих запросов при полном цикле.
- Экспорты идут только в системные «Контакты» или share-sheet — по явному действию пользователя.

## Разрешения

| Разрешение | Зачем |
|---|---|
| `CAMERA`, `FLASHLIGHT` | съёмка визиток (камера обязательна — `uses-feature`) |
| `READ_MEDIA_IMAGES` (13+) / `READ_EXTERNAL_STORAGE` (≤12) | выбор фото из галереи |

## Сборка

### Локально

```bash
flutter pub get
flutter test            # локальные тесты (каталог test/ не публикуется)
flutter analyze         # без ошибок
flutter run
```

Релизные артефакты (нужен Android SDK):

```bash
flutter build apk --flavor samsung --release --split-per-abi
flutter build apk --flavor huawei  --release --split-per-abi
flutter build appbundle --flavor samsung --release
```

- `samsung` — обычный Google-вариант (`com.vccontacts.app`);
- `huawei` — `applicationIdSuffix .huawei`, без GMS (on-device ML Kit работает и без Google Play services).

### Через Docker (CI / машина без Flutter SDK)

Нужен Docker и ~8 ГБ на образ. Четыре стадии: toolchain (Flutter 3.24.5 + Android SDK) → `pub get` → `analyze` + `test` → релизная сборка APK (`--split-per-abi`, только arm64-v8a). AAB по умолчанию не собирается — при необходимости включается `--build-arg BUILD_AAB=true` (см. Dockerfile).

```bash
./build.sh              # samsung + huawei → ./apk/
./build.sh samsung      # только Samsung
./build.sh huawei       # только Huawei
./build.sh --test       # только анализ и тесты, без релизной сборки
```

Результат (`./apk/`):

```
apk/
  app-arm64-v8a-samsung-release.apk    ~42.4 МБ
  app-arm64-v8a-huawei-release.apk     ~42.4 МБ
```

Установка на устройство:

```bash
adb install -r apk/app-arm64-v8a-samsung-release.apk   # Samsung S22+
adb install -r apk/app-arm64-v8a-huawei-release.apk    # Huawei
```

Подпись по умолчанию — debug-ключ Gradle (release-сборка собирается, но так релизовать нельзя). Для релиза добавьте в `android/app/build.gradle.kts` `signingConfigs` с release-keystore, секреты храните в CI — см. чеклист §12 ARCHITECTURE.md.

## Ограничения и известные особенности

- **Кириллица**: поддерживается гибридом — ML Kit (латиница) + Tesseract 5 `rus+eng` как второй движок (`TextRecognitionEngine`). Основной режим режет визитку на области по разметке ML Kit и читает каждую строку Tesseract `rus+eng`; английские области дополнительно перераспознаются ML Kit. Модели Tesseract (tessdata_best) вшиты в APK (~30 МБ), поэтому распознавание остаётся полностью офлайн. Tesseract запускается многопроходно (варианты × psm, выбор по уверенности слов), затем мелкий/неуверенный текст распознаётся по блокам на всех вариантах предобработки, а `BlockConsensus` выбирает результат по кворуму — поэтому шаг распознавания занимает несколько секунд.
- **Фото визитки не сохраняется**: поле `photoPath` есть в модели и схеме БД, но пайплайн его пока не заполняет, превью на экране карточки нет (фото живёт только во временном каталоге до перезапуска).
- **Авто-поиск границ визитки** реализован через OpenCV (`opencv_dart`) — `CardDetector` ищет контур и выпрямляет перспективу, если пользователь не задал ручную рамку. Это best-effort: при ненадёжном контуре или ошибке обработка падает обратно на исходное фото. Поворот выполняется **один раз** по контуру прямоугольника (портрет → 90°), а не по направлению текста; в OCR дополнительно выравнивается только небольшой наклон строк.
- **Размер APK**: из-за вшитых моделей Tesseract и нативной библиотеки OpenCV (`libdartcv.so`) релизный APK для одной ABI весит ~110 МБ.
- **Дубликаты контактов при повторном экспорте не отслеживаются** — каждый экспорт создаёт новый контакт.
- **Интерфейс только на русском** (локализаций/`intl`-переводов нет, `intl` используется для форматирования дат).
- **Каталог `ios/` не сгенерирован**: `flutter create . --platforms=ios` + Info.plist (камера/галерея) — шаг 9 плана MVP; весь код UI/бизнес-логики платформо-независим.
- Карточки без ни одного из полей (имя/компания/телефон/email) сохранить нельзя — кнопка «Сохранить» неактивна.

# VCContacts

Flutter-приложение (Android + iOS) для сканирования визитных карточек с **полностью локальной** обработкой: фото, текст и визитки не покидают устройство. В рантайме нет ни одного сетевого вызова — в манифесте Android даже отсутствует разрешение `INTERNET`.

- Текущая версия: `0.1.0+1`
- UI — русскоязычный, Material 3
- Детальная документация: [ARCHITECTURE.md](ARCHITECTURE.md)

## Как это работает

```
Фото (камера/галерея) → кадрирование → предобработка → OCR на устройстве
→ парсинг полей → экран проверки (человек правит) → локальная БД → экспорт
```

Пошагово:

1. **Съёмка или выбор из галереи** — оба источника ведут в один и тот же поток обработки.
2. **Кадрирование** — рамку с угловыми маркерами можно тянуть пальцем (углы или весь прямоугольник), либо нажать «Без обрезки».
3. **Предобработка** (чистый Dart, пакет `image`): поворот по EXIF → обрезка по рамке → оценка яркости (предупреждения «очень тёмное» / «пересвечено — возможны блики») → ч/б, повышение контраста и нормализация уровней → уменьшение до 1600 px по длинной стороне, JPEG q92 во временный каталог. Дополнительно готовится второй вариант — апскейл мелких кадров до ~1400 px с лёгкой подрезкой резкости (для мелкого/декоративного текста).
4. **OCR на устройстве** — два движка, оба офлайн: Google ML Kit Text Recognition v2 (`TextRecognitionScript.latin`) и Tesseract 5 (`rus+eng`, tessdata_best вшиты в APK). ML Kit даёт чистую латиницу; Tesseract добирает кириллицу, которую ML Kit latin не видит. Tesseract запускается **многопроходно** — каждый вариант предобработки (base / upscale+sharpen) × режимы сегментации `psm 3` и `psm 4`; качество прохода оценивается по средней уверенности слов (`x_wconf` из hOCR), выбирается лучший. Затем `OcrService` выбирает между ML Kit и лучшим проходом Tesseract: кириллица важнее, при прочих равных — более полный текст. Прогресс на экране: предобработка → распознавание → разбор полей → готово, с подписью «Фото не покидает устройство».
5. **Парсинг полей** регулярками и эвристиками: имя, должность, компания, телефон, email, сайт, адрес. Всё, что не распозналось, попадает в список «Прочие строки» — ни одна строка не теряется.
6. **Проверка и правка** — человек подтверждает результат; видит предупреждения; тап по строке из «Прочих строк» добавляет её в заметки. «Сохранить» активно только если заполнено хотя бы одно из полей: имя, компания, телефон, email.
7. **Сохранение** в локальную sqflite-базу (`vc_contacts.db`, таблица `cards`, индексы под поиск и сортировку).

## Функциональность по экранам

### Список визиток (главный)
- Список сохранённых визиток: инициалы, имя/компания, подпись (должность · email), дата обновления; сортировка — по времени обновления (сначала новые).
- Поиск в приложении — по имени, компании, телефону, email (SQL `LIKE`).
- Удаление: долгий тап на карточке или кнопка на экране деталей — с диалогом подтверждения.
- Pull-to-refresh, состояния «пусто» (с подсказкой) и «ошибка» (с кнопкой «Повторить»).
- Две FAB: галерея и камера.
- Меню → «Экспорт всех в CSV» через системный share-sheet.

### Камера
- Превью, автофокус (встроен в контроллер), съёмка JPEG с увеличенной зоной затвора.
- Вспышка тремя режимами: выкл → факел → авто; переключение фронтальная/основная.
- Быстрый доступ к галерее прямо из экрана камеры.
- Разрешения: запрос с объяснением, переход в настройки при permanently-denied, альтернатива «можно из галереи» при отказе.
- Корректное поведение в фоне: контроллер отпускается на `inactive`, пересоздаётся на `resume` (иначе экран захвата «залипает»).

### Обрезка
- Рамка в нормализованных координатах (0..1) — переживает любое разрешение фото; зона захвата угла 44 px; минимальный размер рамки 15%.
- Кнопки: «Без обрезки» и «Сканировать».

### Ход сканирования
- Четырёхшаговый индикатор (предобработка → распознавание → разбор → готово).
- Ошибка → «Повторить» (тот же снимок с той же рамкой) или «Закрыть»; экран сбоя **не пропадает**.
- Пустой OCR — не авария: открывается ручной ввод с баннером «Текст не распознан — заполните карточку вручную».
- **Диагностика OCR** — раскрывающаяся панель на экране проверки (и на экране сбоя): что вернул ML Kit и каждый проход Tesseract (вариант предобработки, psm) — число строк и символов, флаг кириллицы, уверенность в процентах, первые 200 символов распознанного текста или текст ошибки, кого выбрал сервис. Раньше сообщение мелькало и экран заменялся — теперь диагностику можно прочитать и приложить к обращению.

### Проверка/редактирование
- Восемь полей: имя, должность, компания, телефон, email, сайт, адрес, заметки.
- Баннеры-предупреждения (о качестве фото, кириллице, нескольких телефонах и т.п.).
- «Прочие строки с визитки (N)» — раскрывающийся список, тап добавляет строку в заметки.
- Защита от потери данных: при «назад» с несохранёнными правками — диалог «Не сохранять?»; индикатор сохранения на кнопке.

### Карточка (просмотр)
- Шапка с инициалами, именем, подписью и датой обновления.
- Экспорт: «В контакты» (системный Contact Provider) и «vCard» (share-sheet).
- Тап по любому полю — копирование значения в буфер обмена.
- Редактирование и удаление из этого же экрана.

### Экспорт
- **В контакты устройства** (`flutter_contacts`): имя/фамилия разбиваются, организация/должность, телефон (как на визитке — `phoneRaw`), email, сайт, адрес, заметки. Запрос разрешения с rationale, обработка permanently-denied.
- **vCard 3.0** (`N`, `FN`, `ORG`, `TITLE`, `TEL`, `EMAIL`, `URL`, `ADR`, `NOTE`, `REV`) — файл во временном каталоге, отправка через системный share-sheet.
- **CSV всех визиток**: UTF-8 с BOM (Excel открывает кириллицу), разделитель `;`, кавычки экранируются.

## Что распознаётся

| Поле | Как определяется |
|---|---|
| Email | regex; очистка конечной пунктуации |
| Телефон | кандидаты по regex → фильтры (7–15 цифр, отсев лет и индексов) → нормализация в E.164 с приоритетом РФ-форматов (`+7…`, `8…`, `999…`, городские со скобками); исходная строка сохраняется в `phoneRaw` |
| Сайт | явный `https://`/`www.` или «голый» домен с известным TLD + защита от `ACME Corp.` → `acme.co` |
| Адрес | словари `ул/пр/наб/…` и `street/ave/blvd/…` + 6-значный почтовый индекс РФ |
| Имя | скоринг строки (два слова с заглавных, сплит «Имя — Должность» и т.п.) |
| Должность/компания | подстрочные словари ru/en + организационные формы (`ООО/ЗАО/LLC/Ltd/…`) |

Краевые случаи: найдено несколько телефонов — сохраняется лучший по приоритету, остальные — в предупреждении; кириллица — предупреждение «проверьте поля внимательнее»; «Не удалось выделить поля» — ручная правка.

## Хранение

- sqflite, файл `vc_contacts.db` в песочнице приложения; схема v1 с заготовкой под миграции.
- Поля: имя, должность, компания, телефон (`phone` E.164 + `phoneRaw`), email, сайт, адрес, заметки, путь к фото, даты создания/обновления.
- Поиск — SQL `LIKE` по четырём полям; сортировка `updatedAt DESC`.

## Приватность

- В `AndroidManifest.xml` **нет разрешения `INTERNET`** — приложение физически не может открыть сокет.
- ML Kit работает через on-device API, Tesseract — локальная C++-библиотека с моделями в APK; облачный ML Kit, Firebase, аналитика и http-клиенты в зависимостях отсутствуют.
- Проверить можно через `adb shell dumpsys package com.vccontacts.app`, tcpdump на USB-мосте или прокси (Charles/Proxyman): 0 исходящих запросов при полном цикле.
- Экспорты идут только в системные «Контакты» или share-sheet — по явному действию пользователя.

## Разрешения

| Разрешение | Зачем |
|---|---|
| `CAMERA`, `FLASHLIGHT` | съёмка визиток (камера обязательна — `uses-feature`) |
| `READ_MEDIA_IMAGES` (13+) / `READ_EXTERNAL_STORAGE` (≤12) | выбор фото из галереи |
| `READ_CONTACTS`, `WRITE_CONTACTS` | экспорт в контакты устройства |

## Сборка

### Локально

```bash
flutter pub get
flutter test            # 40 юнит-тестов (парсер + выбор движков, многопроходность, hOCR)
flutter analyze         # без ошибок
flutter run
```

Релизные артефакты (нужен Android SDK):

```bash
flutter build apk --flavor samsung --release --split-per-abi
flutter build apk --flavor huawei  --release --split-per-abi
flutter build appbundle --flavor samsung --release
```

- `samsung` — обычный Google-вариант (`com.vccontacts.app`);
- `huawei` — `applicationIdSuffix .huawei`, без GMS (on-device ML Kit работает и без Google Play services).

### Через Docker (CI / машина без Flutter SDK)

Нужен Docker и ~8 ГБ на образ. Четыре стадии: toolchain (Flutter 3.24.5 + Android SDK) → `pub get` → `analyze` + `test` → релизная сборка APK (`--split-per-abi`, только arm64-v8a). AAB по умолчанию не собирается — при необходимости включается `--build-arg BUILD_AAB=true` (см. Dockerfile).

```bash
./build.sh              # samsung + huawei → ./apk/
./build.sh samsung      # только Samsung
./build.sh huawei       # только Huawei
./build.sh --test       # только анализ и тесты, без релизной сборки
```

Результат (`./apk/`):

```
apk/
  app-arm64-v8a-samsung-release.apk    ~42.4 МБ
  app-arm64-v8a-huawei-release.apk     ~42.4 МБ
```

Установка на устройство:

```bash
adb install -r apk/app-arm64-v8a-samsung-release.apk   # Samsung S22+
adb install -r apk/app-arm64-v8a-huawei-release.apk    # Huawei
```

Подпись по умолчанию — debug-ключ Gradle (release-сборка собирается, но так релизовать нельзя). Для релиза добавьте в `android/app/build.gradle.kts` `signingConfigs` с release-keystore, секреты храните в CI — см. чеклист §12 ARCHITECTURE.md.

## Ограничения и известные особенности

- **Кириллица**: поддерживается гибридом — ML Kit (латиница) + Tesseract 5 `rus+eng` как второй движок (`TextRecognitionEngine`). Модели Tesseract (tessdata_best) вшиты в APK (~30 МБ), поэтому распознавание остаётся полностью офлайн. Tesseract запускается многопроходно (варианты × psm, выбор по уверенности слов), поэтому шаг распознавания занимает несколько секунд.
- **Фото визитки не сохраняется**: поле `photoPath` есть в модели и схеме БД, но пайплайн его пока не заполняет, превью на экране карточки нет (фото живёт только во временном каталоге до перезапуска).
- **Коррекции перспективы и авто-поиска границ нет** — кадрирование ручное, обработка чисто Dart; OpenCV — вне MVP.
- **Дубликаты контактов при повторном экспорте не отслеживаются** — каждый экспорт создаёт новый контакт.
- **Интерфейс только на русском** (локализаций/`intl`-переводов нет, `intl` используется для форматирования дат).
- **Каталог `ios/` не сгенерирован**: `flutter create . --platforms=ios` + Info.plist (камера/галерея) — шаг 9 плана MVP; весь код UI/бизнес-логики платформо-независим.
- Карточки без ни одного из полей (имя/компания/телефон/email) сохранить нельзя — кнопка «Сохранить» неактивна.
